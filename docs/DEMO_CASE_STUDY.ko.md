# 실제 작동 데모 — ORBITAL ECHO

[한국어](DEMO_CASE_STUDY.ko.md) · [English](DEMO_CASE_STUDY.md)

이 문서는 고객 작품이나 미공개 에셋을 노출하지 않고 라이트블링거의 실제 제작 흐름을 보여주기 위해 만든 독립 공개 사례입니다.

> 제안·시스템 설계: **AI Creator BAO** · 개발·운영: **STUDIO GENESIS**

## 데모 범위

| 항목 | 결과 |
| --- | ---: |
| 대본 길이 | 42초 |
| 작업 구간 | 2개 |
| 제작 샷 | 6개 |
| 인물 정체성 | 3개 |
| 장소 정체성 | 2개 |
| 동기화 레퍼런스 에셋 | 5개 |
| 프롬프트 정본 | 한글 6 + 영문 6 + 스토리보드 6 |
| 완료 스토리보드 작업 | 3개 |
| 실패 단계 | 0개 |

화면은 실제 라이트블링거 애플리케이션의 격리된 공개 데모 모드에서 캡처했습니다. 실제 UI, API 계약, 데이터 구조, 단계 진행 규칙, 에셋 연결, 프롬프트와 렌더 이력 컴포넌트를 사용하되 외부 모델 비용 없이 같은 결과를 재현할 수 있도록 고정 데이터로 구성했습니다.

## 1. 승인 대본

모델을 사용하는 제작 단계에 들어가기 전에 작가와 감수자가 원문을 승인합니다. 한국어 원본과 영문 번역본은 별도 필드로 보관되므로 한쪽을 편집해도 다른 쪽이 덮어써지지 않습니다.

![라이트블링거 승인 대본](../assets/demo/01-approved-screenplay.png)

- [한국어 승인 대본](../examples/orbital-echo/input-screenplay.ko.txt)
- [English screenplay](../examples/orbital-echo/input-screenplay.en.txt)

## 2. 구간 탐색기와 샷·타이밍

42초 대본을 2개의 안정적인 작업 구간으로 나눴습니다. 전체 에피소드의 모든 샷을 한 화면에 펼치지 않고, 구간 목록에서 하나를 선택한 뒤 그 안의 샷을 한 개씩 편집합니다. 실패한 구간도 순서를 잃지 않고 제자리에서 재시도할 수 있습니다.

![구간 탐색기와 샷 타이밍](../assets/demo/02-shot-design.png)

`DEMO-SH002`에는 9초 타이밍, 미디엄 클로즈업, 고정 카메라, 대사, 시각·청각 지문과 연기 지시가 각각 독립 필드로 저장됩니다.

- [한국어 샷 데이터](../examples/orbital-echo/shot-output.sample.json)
- [English shot data](../examples/orbital-echo/shot-output.sample.en.json)

## 3. 연속성과 에셋 동기화

인물과 장소는 프롬프트에 반복 입력하는 이름이 아니라 제작 정체성입니다. 각 샷에 실제로 보이는 인물과 장소만 `@에셋명`으로 연결하며, 같은 구간 안에서도 샷마다 다른 조합을 사용할 수 있습니다.

![연속성과 에셋 동기화](../assets/demo/03-continuity-assets.png)

- `@ARIA_PILOT` — 조종사 아리아
- `@NOX_NAV` — 청색 항법 홀로그램 녹스
- `@WARDEN7_DRONE` — 여섯 다리 정찰 드론 워든-7
- `@LB_OBSERVATION` — 라이트블링거 관측실
- `@LB_BREACH` — 우현 파손 구역

## 4. 한글·영문 프롬프트 정본

샷과 타이밍, 연속성 에셋이 확정된 뒤에만 프롬프트를 생성합니다. 공통 룩과 공통 네거티브는 씬 상단에서 한 번 관리하고, 각 샷에는 다음 정본을 함께 보존합니다.

- 감독·감수자를 위한 한글 정본
- 영상 생성 엔진에 전달할 영문 정본
- 정지 스토리보드용 영문 정본
- 정체성·구도·블로킹·행동·룩·오디오·네거티브 7레이어
- 해당 샷에만 필요한 추가 네거티브

![프롬프트 정본 편집](../assets/demo/04-prompt-master.png)

[한/영 프롬프트 정본 JSON](../examples/orbital-echo/prompt-master.sample.json)에서 같은 샷의 두 언어와 구조화 레이어를 함께 확인할 수 있습니다.

## 5. 비용 승인과 결과 이력

렌더 실행 전에 대상 샷과 예상 크레딧을 확인합니다. 완료·실패·재생성 결과는 덮어쓰지 않고 샷별 이력으로 보관합니다.

## 이 데모가 증명하는 것

1. 승인 대본이 끝까지 제작 기준으로 남습니다.
2. 장편 대본을 안정적인 구간과 탐색기로 관리합니다.
3. 대사·지문·연기·카메라·타이밍을 사람이 수정하고 확정할 수 있습니다.
4. 프롬프트보다 먼저 인물과 장소의 정체성을 잠급니다.
5. 한국어 검수 의도와 영문 생성 입력을 함께 추적합니다.
6. 비용이 드는 렌더 앞에는 사람의 승인이 있습니다.
7. 성공·실패·재시도 결과의 계보를 보존합니다.

상용 애플리케이션 전체 소스, 계정, 비밀키, 고객 미디어는 공개 저장소에 포함하지 않습니다. 이 저장소는 워크플로우 검증을 위한 정제된 입력, 대표 출력, 화면과 데이터 구조를 제공합니다.
